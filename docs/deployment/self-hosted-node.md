# 803见势研究自托管运维指南

本指南面向前端与 MySQL 部署在同一台服务器或同一内网的场景。本文只说明部署和只读验证；不会授权创建表、修改表、写入研究结果或改变数据库账号权限。

## 运行前检查

- Node.js 版本必须为 `>=22.13.0`。
- 使用仓库锁定的依赖版本，不用全局安装替代项目依赖。
- 生产环境把 MySQL 仅暴露给本机回环地址或受控内网；网页服务不依赖 SSH 隧道。
- 将实际环境变量保存在服务器的受保护文件或进程管理器配置中，不能提交进 Git、压缩包或日志。

## 构建与启动

在项目根目录执行：

```bash
npm ci
npm run build
npm run start
```

`npm run start` 直接运行 `.next/standalone/server.js`。`npm run build` 的 `postbuild` 会把 `public` 和 `.next/static` 复制到 `.next/standalone`，因此本机构建后可直接启动。

生产部署时只需复制 `.next/standalone` 的内容到部署目录；在部署目录配置环境变量后执行 `node server.js`。

独立产物不包含自动注入的环境文件；应由服务器的进程管理器、受保护环境文件或密钥管理系统提供变量。切换发布版本前，先在新目录完成构建并确认服务可启动，再切换反向代理或进程指向。

## 环境变量与最小权限

服务端读取下列变量；变量名可出现在配置中，但真实值不能写进仓库或运维文档。

| 变量 | 含义 |
| --- | --- |
| `MYSQL_HOST` | MySQL 地址；同机优先使用回环地址 |
| `MYSQL_PORT` | MySQL 端口 |
| `MYSQL_DATABASE` | 目标数据库 |
| `MYSQL_USER` | 网页查询专用账号 |
| `MYSQL_PASSWORD` | 网页查询专用账号密码 |
| `MYSQL_CONNECTION_LIMIT` | MySQL 连接池最大连接数 |

网页服务账号应只拥有研究页面查询所需库表的 `SELECT` 权限，且不拥有 `CREATE`、`ALTER`、`DROP`、`INSERT`、`UPDATE`、`DELETE`、`REPLACE`、`TRUNCATE` 或授权管理权限。批处理账号若将来获准启用，应与网页账号分离，并只赋予必要的原始行情读取权限和结果表写入权限。

应用的数据访问层额外限制为只读 SQL；即使环境配置错误，也不应把网页运行账号当作数据写入账号使用。

## 日期与时区

- 首页和研究页标题日期由服务端按 `Asia/Shanghai` 计算，前端不根据访客设备时间重新计算。
- 服务端日期接口和研究接口均禁止缓存；页面在重新可见时会刷新服务器上下文。
- IPO 事件、数据截止时间和信息发布时间是数据库业务时间，应按数据库值显示，不能用服务器当天日期覆盖。
- 数据缺失、表未创建或最新批次不可用时显示 `XX` 与数据状态；零值 `0` 是有效值，不能替换成 `XX`。

## MySQL 网络与只读盘点

部署在同一台服务器时，优先配置 `MYSQL_HOST` 为本机回环地址。若 MySQL 与网页服务在同一私网，限制防火墙和数据库监听范围到该私网；不要为网页运行时开放公网数据库端口或依赖 SSH 隧道。

仅在配置好只读账号后，可运行以下只读结构盘点：

```bash
npm run db:audit
```

该命令只查询 `information_schema` 以输出表、字段和索引的可复用性，不读取业务样本数据，也不会执行 DDL 或 DML。

## 数据库结构授权闸门

[mysql-research-schema-proposal.sql](../database/mysql-research-schema-proposal.sql) 是评审草案，不是部署脚本。它明确标记为“未经用户明确批准不得执行”。

在取得单独、明确的建表/改表授权前：

- 不运行该 SQL 文件。
- 不执行迁移、建表、改表、初始化或任何写入语句。
- 不为批处理创建或升级数据库权限。
- 页面继续通过稳定的空数据状态显示 `XX`。

获批后也应先在备份环境审阅 SQL、确认已有表的复用关系、记录变更窗口，再由有权限的数据库管理员执行。

## 16:10 策略批处理

策略程序默认是只读演练，用于验证当日 `daily`、`daily_basic` 和 `adj_factor` 的最新共同交易日和筛选逻辑：

```bash
npm run strategy:dry-run
```

建议在交易日 `16:10`（`Asia/Shanghai`）由系统定时器或受控任务调度器调用该命令；应记录退出状态和标准错误，但不得把环境变量输出到日志。默认命令不会写入数据库。

写入研究结果需要两个运行时开关，并且只能在用户另行明确授权了建表、写入与调度后实施。当前阶段不应设置这些开关，也不应将写入命令加入 crontab、systemd timer 或 CI。

## 备份、发布与回滚

发布前：

1. 记录当前正在运行的版本、构建时间和环境文件位置（不要记录密钥内容）。
2. 保存上一份可运行的独立产物或完整项目构建目录。
3. 若未来涉及已获批的数据库变更，由数据库管理员在变更前完成可恢复备份并演练恢复；本轮不涉及数据库变更。

出现页面或接口问题时，先回滚网页服务到上一份已验证的构建目录并重启该服务。由于当前运行时只读，网页版本回滚不会修改 MySQL 数据。若未来发生已获批的数据库迁移，应按该迁移的专属回滚预案处理，不能把网页代码回滚当作数据库回滚。

## 上线前最小验证

```bash
npm run test:unit
npm run lint
npm run build
node --test tests/rendered-html.test.mjs
```

确认首页与 `#today`、`#risk`、`#strategy`、`#ipo` 均可访问；确认策略02不存在；在无研究数据时确认页面显示 `XX` 和正确状态而非旧的静态行情。完成验证后仅在用户明确要求发布时再执行实际对外发布。
