# 803见势研究服务器日期与 MySQL 研究数据接入设计

## 目标与边界

本轮把现有原型调整为可在同一台云服务器上运行的标准 Next.js Node 应用，并为“今日决策台、风控提醒、策略信号观察、IPO 专题”建立真实 MySQL 数据读取链路。

- 页面标题区域的“今日日期”由服务端按 `Asia/Shanghai` 生成，前端不使用浏览器时间、不写死日期。
- IPO 节点、信息发布时间、数据批次时间等业务日期从数据库读取，不用服务器当天日期覆盖历史事实。
- 策略信号观察只保留策略01；删除策略02“估值修复”及其候选、筛选分支、演示文案和测试。
- 研究四模块不再使用静态演示数值；数据库字段缺失时在原位置显示 `XX`，不得编造或偷偷回退到旧的静态数据。
- 会员购买、支付、兑换码和会员到期时间暂时保留原型演示，不接数据库。
- 本轮可以编写数据库结构建议、迁移草案和批处理程序，但未经用户单独授权，不在现有数据库执行 DDL、建表、改表或初始化数据。

## 现状依据

工作区中的 `A_stock_user_schema.sql` 显示现有 `A_stock` 库至少有 `adj_factor`、`daily`、`daily_basic`、`index_basic`、`index_daily` 五张行情基础表。DBeaver 查询脚本还引用了 `call_auction`，说明导出后数据库可能已有新增表；实施前先通过 `information_schema` 做一次只读实时盘点，发现同义表时直接复用，不重复设计。

当前项目使用 React 19、Next.js 16 API 形式和 Vinext/Cloudflare Worker 构建目标。用户已选择网页服务与 MySQL 部署在同一台云服务器，因此改为标准 Next.js Node 运行时，保留现有页面外观、hash 导航、动画和响应式交互。

## 应用架构

### 服务端与数据访问

- 使用标准 `next dev`、`next build`、`next start`，生产构建启用 `output: "standalone"`。
- 使用 `mysql2` 连接池和 server-only 数据仓库层；浏览器永远接触不到数据库主机、账号或密码。
- 本地开发可通过用户已有 SSH 隧道连接；生产环境使用云服务器上的 `127.0.0.1:3306` 或内网地址直连，运行时不依赖 SSH 隧道。
- 凭据只从未提交的环境变量读取。仓库只提供无敏感值的 `.env.example`。
- 建议后续创建两个最小权限账号：网页账号只读所需表；批处理账号只读行情表并只写研究结果表。本轮不执行账号创建。

### 接口与刷新

提供以下只读 Route Handlers：

- `GET /api/system/context`：服务器日期、时区和当前交易日状态。
- `GET /api/research/today`：今日决策摘要、最新风控摘要、策略01候选预览、信息流和事件。
- `GET /api/research/risk`：最新风险批次、信号、时间层和极端条件。
- `GET /api/research/strategy`：策略01定义、运行状态、漏斗、正式/临近候选和证据。
- `GET /api/research/ipo`：IPO 公司、进度、对比指标、中签测算、估值情景和公开事件。

统一响应包络：

```ts
type ResearchResponse<T> = {
  serverDate: string;
  timezone: "Asia/Shanghai";
  status: "ready" | "pending" | "partial" | "missing" | "failed";
  batchId: string | null;
  dataAsOf: string | null;
  missingFields: string[];
  data: T;
};
```

所有接口禁用静态缓存。页面首次渲染获得服务器日期，之后每五分钟以及标签页重新可见时重新获取一次；日期值始终来自服务器。研究模块进入页面时读取对应接口，失败时保留页面结构并显示 `XX` 和明确的数据状态。

## 数据库建议：混合模式

关键身份、日期、数值、状态和关联关系使用普通字段，变化频繁的展示详情使用 MySQL `JSON`。每个结果都关联 `research_batch`，做到可追溯、可重跑且不会把失败批次当成最新结果。

### 优先补齐的基础数据表

| 建议表 | 用途 | 前端位置 |
| --- | --- | --- |
| `stock_basic` | 股票名称、板块、行业、上市状态 | 策略候选名称/市场/板块；风控行业聚合 |
| `trade_calendar` | 交易日、前一交易日、开闭市 | 顶部市场状态；批处理应运行的交易日 |
| `stock_limit_price` | 每股每日涨跌停价格 | 风控“跌停扩散”；策略涨停/缺口证据 |
| `external_market_quote` | A50 等隔夜市场快照 | 风控“隔夜压力”信号 |
| `market_event` | 政策、财报、宏观等日历事件 | 今日决策台事件列表 |
| `intel_item` | 作者、来源、发布时间、标签、正文摘要、链接 | 今日决策台“今日信息”筛选和信息卡片 |

`daily`、`daily_basic`、`adj_factor`、`index_basic`、`index_daily` 和已存在的 `call_auction` 继续作为行情原始层，不复制数据。

### 研究批次与今日决策台

| 建议表 | 核心字段/JSON | 前端位置 |
| --- | --- | --- |
| `research_batch` | 模块、交易日、批次号、状态、开始/完成时间、数据截止时间、错误信息 | 四模块批次标签、加载/失败/部分状态 |
| `daily_decision_snapshot` | 市场阶段、标题、摘要、行动说明、`summary_points_json` | 今日决策台主摘要和三条结论 |

今日决策台的风控卡和策略候选不复制，分别读取最新有效的风险批次和策略01批次。

### 风控结果

| 建议表 | 核心字段/JSON | 前端位置 |
| --- | --- | --- |
| `risk_snapshot` | 分数、阶段、系数、敞口、数据层、摘要、行动说明、`timeline_json`、`kill_conditions_json` | 风控总览、更新时间层、极端条件 |
| `risk_signal_result` | 信号编码、展示值、分位、阈值、贡献、状态、说明、排序 | 六项风险信号卡片 |

前端只显示最新成功批次；当天批次尚未完成时显示 `pending` 和 `XX`，不把上一交易日结果伪装成今天。

### 策略01结果

| 建议表 | 核心字段/JSON | 前端位置 |
| --- | --- | --- |
| `strategy_definition` | 固定代码、版本、名称、说明、是否启用、`rules_json` | 策略01说明和规则路径 |
| `strategy_run` | 策略、交易日、状态、全市场样本数、正式/临近数量、耗时 | 运行状态和批次说明 |
| `strategy_funnel_result` | 步骤编码、名称、通过数量、排序 | “今日筛选漏斗” |
| `strategy_candidate` | 股票代码、结果类型、评分、收盘价、涨跌幅、缺口、量比、形态、原因、`evidence_json` | 候选表、临近阈值表和证据抽屉 |

策略代码固定为 `momentum-gap-volume`。收盘行情完整后由定时任务运行，建议交易日 `16:10` 开始：先确认 `daily`、`daily_basic`、`adj_factor` 的最新公共交易日，再计算漏斗和候选，最后在同一事务内将批次标记为成功。运行失败只记录失败状态，不覆盖上一个成功批次。

### IPO 专题

| 建议表 | 核心字段/JSON | 前端位置 |
| --- | --- | --- |
| `ipo_company` | 公司代码、名称、全称、交易所、板块、行业、股票代码、当前状态 | 长鑫/宇树概览及蓝箭航天/中科宇航卡片 |
| `ipo_stage_event` | 阶段、事件日期、完成状态、说明、来源链接、排序 | “发行上市进度对比”和商业航天进度/事件 |
| `ipo_metric_snapshot` | 截止时间、`metrics_json`、来源 | 公司对比表和概览指标 |
| `ipo_subscription_analysis` | 发行量、募资额、发行价、顶格股数、所需市值、配号数、中签率、测算口径 | “中签难度对比” |
| `ipo_valuation_scenario` | 情景价格、流通股数、总股数、流通市值、总市值 | 宇树科技价格/市值情景表 |

IPO 中已经移除的“关键时间线”和“观察变量与主要风险”不恢复。每条公开信息保留来源名称、来源链接和发布时间；缺少任一数值时仅该字段显示 `XX`。

## 前端行为

- 顶部市场状态、首页研究日期、今日决策台/风控/策略/IPO 标题日期统一读取 `serverDate`，格式由共享格式化函数输出。
- 删除 `RESEARCH_SNAPSHOT` 中用于研究页面的固定日期、批次和研究数据；会员演示字段暂时单独保留，避免研究数据与演示支付混用。
- 策略页删除两策略选择器，直接展示策略01。删除 `quality` 类型、候选数据、漏斗分支和相关浏览器测试。
- 每个字段的 `null`、`undefined`、空字符串和非有限数值统一转换为 `XX`；零值是有效数据，不得转换为 `XX`。
- 请求失败、无批次、批次运行中和部分缺失使用不同状态文案；页面不崩溃、不清空导航、不显示伪造数据。

## 验证与验收

- 单元测试覆盖服务器日期格式、`XX` 规则、统一响应包络、最新成功批次选择和策略01筛选。
- 数据仓库测试使用独立测试夹具，覆盖正常数据、空表、部分字段缺失和数据库异常；不对生产数据库写入。
- 源码测试确认不存在策略02、`quality` 候选和研究页面硬编码快照日期。
- API 集成测试确认五个接口状态码、无缓存头、敏感字段不泄露，并在无数据时返回稳定结构。
- 页面测试覆盖四模块正常/待处理/缺失/失败状态、策略正式与临近候选、IPO 局部 `XX`、移动端和键盘操作。
- 最终运行单元测试、lint、标准 Next.js 生产构建和本地浏览器冒烟检查；本轮不发布。

## 实施顺序与授权闸门

1. 只读盘点实时数据库，输出“已存在/可复用/确实缺失”的表与字段清单。
2. 迁移到标准 Next.js Node，完成服务器日期和 MySQL 只读访问层。
3. 移除策略02，接入研究四模块的真实读取和 `XX` 降级。
4. 提交混合模式建表 SQL 草案和页面映射文档，但不执行。
5. 只有收到用户明确的建表授权后，才创建结果表、启用批处理写入和生产定时任务。
